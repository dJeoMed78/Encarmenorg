# Sesión inicial de memoria — FreeLLMAPI
**Fecha:** 2026-11-17  
**Rama:** `experiment/freellmapi-evaluation-20261116`

## Resumen fiel de la conversación
1. El propietario solicitó incorporar FreeLLMAPI a un apartado experimental de GitHub y evaluarlo como solución de programación/IA sin sobrecargar Hostinger ni su computadora.
2. Se configuró un adaptador experimental en Vercel con Gemini como proveedor inicial.
3. Se creó una interfaz web de chat privada y se configuró acceso mediante variable sensible de Vercel.
4. Se revocó una clave Gemini que el propietario había pegado en el chat. No registrar su valor.
5. Se incorporó Groq como segundo proveedor y un selector visual Gemini/Groq.
6. El propietario preguntó por failover automático. Se detectó que el código inicial solo devolvía error 429 y no cambiaba de proveedor.
7. Se agregó código de fallback para errores temporales y cuotas (429, 500, 502, 503, 504 y timeout), y se agregó la opción Automático en el selector. Falta verificar despliegue y prueba real.
8. El propietario pidió guardar el historial en GitHub para que un modelo alternativo pueda continuar el proyecto. Se creó esta estructura documental.

## Estado verificado por código, no por pruebas de ejecución
- Rutas de proveedor Gemini y Groq presentes en el código.
- Código de fallback automático presente en la rama.
- Opción Automático presente en la interfaz de la rama.
- No se ha demostrado todavía una prueba de fallback real extremo a extremo.
- No hay token de GitHub configurado en Vercel; persistencia automática de transcripciones no está implementada.
